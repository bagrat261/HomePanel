# Продолжение HomePanel на Mac

Репозиторий: https://github.com/bagrat261/HomePanel

Если репозиторий ещё не открыт локально:

```sh
git clone https://github.com/bagrat261/HomePanel.git
cd HomePanel
```

Ты работаешь над существующим проектом HomePanel. Продолжай реализацию, а не
ограничивайся архитектурой или рекомендациями. Сначала прочитай README.md,
docs/VERIFICATION.md, ios/README.md и актуальный код. Проверь действительное
состояние файлов и toolchain; описание ниже не заменяет проверку.

## Что нужно пользователю

- **Нативное устанавливаемое приложение для iPad 2 на iOS 9.3.5/9.3.6, ARMv7.**
  Итоговый артефакт — настоящий IPA. Приоритетная установка через jailbreak;
  Sideloadly — возможный запасной вариант при подходящей подписи.
- Не Windows-приложение, не PWA, не сайт, переименованный в IPA, не WebView-обёртка
  в качестве объяснения низкой нагрузки. Windows в предыдущей работе был только dev-средой.
- Дизайн в узнаваемой стилистике Home Assistant: нейтральные поверхности,
  голубой акцент, компактные карточки, понятные состояния и большие touch-цели.
  Текущий оливковый дизайн пользователю не понравился; его нужно переделать.
- **Настоящий интерфейс/плеер Music Assistant**, а не наш самодельный большой плеер.
  По умолчанию доступен только плеер; максимум дополнительно плейлисты.
  Из обычного Dashboard не должно быть пути в настройки MA.
- Главный приоритет — плавность на старом iPad и малая нагрузка на него.
  Пользователь заинтересован в переносе отрисовки на сервер рядом с HA:
  сервер исполняет UI, iPad получает изображение и отправляет касания обратно.
  Перенос нагрузки не означает нулевое декодирование или отсутствие задержки.

## Что действительно готово

- FastAPI backend, YAML/env конфигурация, изолированный интерактивный Demo Mode.
- HA REST adapter: кэш состояний, reconnect/backoff, таймауты, без автоматического
  повторения управляющих POST. Все HA-секреты на сервере.
- Сессии, CSRF, trusted hosts, фиксированный словарь действий, allowlist entity_id.
- Устройства light/switch/climate/sensor/binary_sensor/button/script/scene,
  сценарии, погода/ПК из явно выбранных сущностей.
- ES5/XHR веб-прототип с собственным мини/большим плеером через HA media_player,
  темами и ночным режимом. Это временный прототип и возможный серверный render source.
- Docker/Compose и исходная локальная упаковка HAOS app, MIT, CI конфигурация.
- На Windows прошли **42 pytest теста**, Ruff, Acorn ES5, uv build и взаимодействия
  в современном Edge. Подробности и ограничения в docs/VERIFICATION.md.
- В ios/ сохранён **непроверенный черновик** Annex B parser и AVSampleBufferDisplayLayer.
  Нет app delegate, сетевого клиента, Xcode-проекта или IPA. В ios/README.md отмечена
  известная ошибка обработки переполнения: исправь её до использования либо перепиши
  этот небольшой черновик с тестами. Не считай исходники работающим приложением.

## Что только обсуждалось, но НЕ реализовано

- Native app, Xcode project, сборка ARMv7 и упаковка IPA.
- Серверный Chromium, захват кадров, FFmpeg/H.264 и отправка касаний.
- Открытие настоящего MA frontend и ограничения kiosk.
- Редизайн в сторону HA.
- Реальные подключения HA/MA, установка на HAOS и тестирование на iPad.

## Направление реализации

1. Проверь Mac: macOS, `xcode-select -p`, `xcodebuild -version`, доступные iPhoneOS SDK,
   наличие поддержки ARMv7 и deployment target iOS 9. Не полагайся на современный
   Xcode: Apple прекратила 32-bit builds начиная с Xcode 14. Исследуй совместимый
   легально установленный toolchain (например Xcode 10.1) и его совместимость с macOS.
   Не скачивай SDK из неофициальных репозиториев и не создавай фиктивный IPA.
2. Приведи UI к HA-стилистике. Зафиксируй токены в DESIGN.md, проверь 1024×768.
3. Сделай один проверяемый вертикальный срез remote display: серверный Dashboard →
   видеопоток → нативное отображение на iPad → одно касание → наблюдаемое изменение.
   Сравни реальную задержку и нагрузку; если подход не даёт плавности, объясни
   результаты и предложи минимальное обоснованное изменение транспорта.
4. Предпочтительное исследуемое направление: H.264 Baseline, без B-frames,
   repeat SPS/PPS, AUD, короткий GOP, bounded queues, свежие кадры вместо накопления.
   Начальная гипотеза 1024×720 (плюс native toolbar 48px), 15 fps; это **не обещание
   плавности**, не результат benchmark и не запрет улучшить параметры после измерений.
   JPEG/MJPEG не выдавай за гарантированное снижение CPU и плавность.
5. Нативный клиент: Objective-C/UIKit, NSURLSession, CoreMedia/AVFoundation,
   AVSampleBufferDisplayLayer или другой доказанно совместимый hardware decode path.
   Никаких iOS 10+ API, SF Symbols или современных Swift runtime требований.
   Проверь, что выбранный путь реально работает на iPad 2, а не только в симуляторе.
6. Серверный renderer — отдельный сервис/app рядом с HA, не патч HA Core.
   Дополнительный Chromium/FFmpeg не должен неограниченно загружать HA-хост.
   Выдели опциональные зависимости и контейнер/HAOS упаковку; ничего не устанавливай
   в реальный HA автоматически. Сохрани запуск базового backend без renderer.
7. Открой на сервере **реальный MA frontend**. Штатные URL-параметры `frameless=true`,
   `player=...`, `showFullscreenPlayer=true` описаны в официальной документации.
   Используй отдельного ограниченного пользователя MA и его серверный токен.
   Скрытое меню — не механизм авторизации. Ограничь маршруты и внешнюю навигацию,
   но не называй DOM/CSS-скрытие безопасным запретом настроек.
8. Не передавай HA/MA токены в приложение. Ввод координат — только авторизованная
   сессия, CSRF/эквивалентная защита, проверенные диапазоны, выбранная поверхность,
   запрет произвольных URL/JavaScript. Устаревшие касания после смены экрана отклоняй.
   Для начала допускается один клиент, но не разделяй чужие экраны/сессии незаметно.
9. Сон/фон: остановка видеопотока и reconnect, idleTimerDisabled только при активном
   отображении, видимый offline, недоступность касаний без актуального изображения.
   Пароль панели не сохраняй открытым текстом; настройки подключения без HA-токена.
10. Собери реальный ARMv7 `.app`, проверь Mach-O и минимальную iOS, затем упакуй
    `Payload/HomePanel.app` в IPA. Jailbreak-вариант без обычной подписи пометь явно;
    подписанный вариант собирай только с реально предоставленными provisioning assets.
    Не считай jailbreak или Sideloadly гарантией совместимости неподходящего бинарника.

## Предварительный протокол (предложение, кода ещё нет)

Существующая авторизация: GET /api/session, POST /api/login {password},
cookie homepanel_session и X-CSRF-Token для изменяющих запросов.

- GET /api/display/status → enabled, width, height, fps, surfaces, generation.
- POST /api/display/surface {surface: dashboard|music|playlists} → generation.
- GET /api/display/stream.h264 → Annex B H.264, авторизованная сессия.
- POST /api/display/input {generation, kind: tap, x, y}; swipe добавляет end_x/end_y.
  Координаты нормализованы 0..1 и считаются только внутри реального video rect.

Это исходная договорённость, которую можно уточнить после проверки транспорта.
Ни одного /api/display endpoint сейчас в backend нет.

## Как проверить и что отдать

- `uv sync --extra dev`, `uv run pytest`, Ruff, `npm ci --ignore-scripts`,
  `npm run check:es5` для сохраняемой веб-части. Не выполняй реальные HA-команды в тестах.
- Отдельные тесты stream parser, границ NAL/access unit, disconnect/reconnect,
  авторизации, доступа к MA settings, устаревших касаний и ограничений памяти.
- Серверный smoke-test: кадры воспроизводятся, задержка не накапливается, касание
  действует на правильную поверхность. Измерь fps, latency, CPU/RAM и bandwidth.
- Передай IPA, исходники, команду сборки, версии toolchain, инструкцию установки
  и честный список непроверенного. Если реального iPad нет, не заявляй его проверку.
- Сохрани результат в GitHub. Не коммить .env, сертификаты, ключи, provisioning,
  локальные токены, личные конфигурации и build-каталоги.
