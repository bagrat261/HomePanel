# Серверная отрисовка, Music Assistant и измерения

[English](REMOTE-DISPLAY.md) · [Установка IPA](../ios/README.ru.md)

HomePanel состоит из нативного клиента для iPad и опционального модуля
отрисовки в сервере HomePanel. Это отдельное приложение рядом с Home Assistant,
не изменение HA Core. Chromium выполняет интерфейс панели или настоящий
интерфейс Music Assistant. Снимки JPEG обрабатываются только на сервере;
PyAV/FFmpeg libx264 кодирует H.264, который передаётся на iPad.

## Запуск сервера

Из корня репозитория:

```sh
uv sync --extra dev --extra renderer
uv run python -m playwright install chromium
HOMEPANEL_DISPLAY_ENABLED=true uv run uvicorn homepanel.app:app --host 0.0.0.0 --port 8090 --workers 1
```

Для доступа с iPad добавьте IP или имя сервера в `allowed_hosts` и задайте
уникальный `PANEL_PASSWORD`. Подключение настоящего Home Assistant описано
в [главном README](../README.md#подключение-home-assistant).

Внутренний адрес панели для Chromium по умолчанию — `http://127.0.0.1:8090`.
Если сервер слушает другой адрес или порт, измените `display.dashboard_url`.
Используйте **ровно один процесс сервера** (`--workers 1`): сессии и владение
экраном хранятся в памяти процесса.

Отрисовка по умолчанию выключена. Обычный сервер продолжает работать без
опциональных зависимостей видеопотока.

## Необязательный запуск в Docker

```sh
docker compose -f docker-compose.renderer.yml up --build
```

Подготовлен отдельный Dockerfile и ограничения: 2 CPU, 1 GiB памяти, 128 процессов
и 256 MiB общей памяти. **Сборка и запуск этого контейнера здесь не проверены.**
Порт по умолчанию доступен только с самого сервера; для домашней сети привязку
нужно изменить осознанно.

Реальный Home Assistant и HAOS не изменялись. Отдельной упаковки видеомодуля
для HAOS пока нет; прежний пакет HAOS относится к базовому серверу.

## Настройка настоящего Music Assistant

1. Создайте в MA отдельного ограниченного пользователя с доступом только
   к нужным плеерам и источникам музыки.
2. Создайте долгоживущий токен именно этого пользователя.
3. Задайте на сервере переменные `MA_URL` и `MA_TOKEN` через окружение или
   механизм хранения секретов. Не используйте токен администратора, не передавайте
   токен на iPad и не добавляйте его в Git.
4. Добавьте в свою закрытую YAML-конфигурацию:

```yaml
display:
  enabled: true
  dashboard_url: http://127.0.0.1:8090
  fps: 15
  music_player: Livingroom
  music_restricted_user: true
```

Вместо `Livingroom` укажите имя своего плеера в MA.

`music_restricted_user` отмечает настройку, выполненную владельцем сервера;
этот флаг **не проверяет права пользователя**. Ограничения прав должен обеспечивать
сам Music Assistant. Пока настройка отсутствует, «Музыка» возвращает 503,
а не открывает подменный плеер.

Сервер открывает официальный интерфейс с параметрами
`?code=...#/home?player=...&frameless=true&showFullscreenPlayer=true`.
Внешние HTTP-переходы, всплывающие окна и маршруты за пределами выбранного
экрана блокируются либо останавливают поток до следующего снимка.
В нативном приложении нет кнопки перехода к настройкам MA.

Диалоги, которые не меняют маршрут, зависят от прав пользователя MA.
Скрытие меню и `frameless` не являются механизмом авторизации.
Плейлисты в этом первом варианте не включены.

Официальные источники:
[параметры открытия интерфейса](https://www.music-assistant.io/faq/how-to/),
[управление пользователями](https://www.music-assistant.io/settings/user-management/).
Без доступа к настоящему MA воспроизведение, права ограниченного пользователя
и недоступность каждого диалога настроек остаются непроверенными.

## Протокол и ограничения ресурсов

| Запрос | Назначение |
|---|---|
| GET `/api/display/status` | Статус функции и размер 1024×720; требуется сессия |
| POST `/api/display/surface` | Выбор `dashboard` или `music`, возвращает номер поколения экрана; требуется CSRF |
| GET `/api/display/stream.h264?generation=N` | Поток Annex B H.264; требуется сессия |
| POST `/api/display/input` | Касание или свайп с поколением экрана, номером кадра и координатами; требуется CSRF |

Координаты `x`/`y` нормализованы от 0 до 1. Для свайпа дополнительно обязательны
`end_x`/`end_y`. Передавать произвольные URL или JavaScript нельзя.

Экран принадлежит одной сессии. Другие сессии получают 409. Новый процесс
отрисовки допускается только после завершения предыдущего.
Очередь видео содержит максимум два независимых кадра, очередь ввода — четыре
события. Размер сжатого кадра ограничен 2 MiB.

Кадры старше двух секунд, неизвестные номера кадров и ввод от прежнего поколения
экрана отклоняются. Возраст повторно проверяется перед выполнением события.
Хранятся отметки времени последних 32 кадров. Номер кадра передаётся в SEI
с идентификатором `HomePanelFrameID` и связывает касание с полученным изображением.

Все кадры — ключевые IDR, с повторением SPS/PPS и AUD, без B-кадров;
H.264 Baseline уровня 3.1, максимум 15 fps. Это позволяет безопасно отбрасывать
накопившиеся кадры ценой меньшей эффективности сжатия.

Без новых поставленных на отображение кадров приложение отключает касания
через две секунды. Эта отметка времени **не измеряет фактическое появление
изображения на экране**. Буферизация TCP и прокси требует проверки на реальной
сети. Для этого адреса видеопотока отключайте буферизацию обратного прокси.

## Измерения на Mac

Команда проверки:
`HOMEPANEL_BENCH_PID=<uvicorn-pid> .venv/bin/python scripts/display-smoke.py`.
Вместо `<uvicorn-pid>` подставьте PID процесса сервера.

Проверка работает только в изолированном Demo: переключает первый демо-свет,
декодирует настоящий H.264, обнаруживает изменение пикселей карточки и подтверждает
изменение состояния сущности. Настоящие команды HA не отправляются.

Условия: Mac ARM64, macOS 26.6.2, локальное соединение, 1024×720, задано 15 fps.
Последний короткий прогон — 48 кадров:

| Показатель | Результат |
|---|---:|
| Полученная частота кадров | 14,31 fps |
| Медианный / максимальный интервал кадров | 67,09 / 117,79 мс |
| От начала сессии до первого декодированного кадра | 1,03 с |
| От касания до изменённого декодированного кадра | 94,33 мс |
| Средний трафик за сессию, включая запуск | 2,00 Мбит/с |
| CPU сервера и дочерних процессов, где одно ядро = 100% | 49,68% |
| Выборочный максимум суммы RSS сервера и дочерних процессов | 568,36 MiB |

Это короткий прогон, не исследование перцентилей и не проверка длительной нагрузки.
Его запуск пересёкся с браузерной проверкой на том же Mac, поэтому компьютер
не был полностью свободен. Предыдущий изолированный прогон из 49 кадров дал
14,37 fps, 134,55 мс до изменённого кадра, 48,88% CPU и 531,89 MiB RSS.
В последнем прогоне Demo-свет изменился off→on, в предыдущем — on→off.
Суммирование RSS может учитывать общую память несколько раз.
Ранее холодный запуск занимал 10,75 с.

Chromium и кодирование создают заметную нагрузку на слабый сервер HA.
**CPU и память iPad, задержка Wi-Fi, аппаратного декодера и фактическое время
касание → экран iPad не измерены.** Обещать плавность на iPad 2 пока нельзя.
Перед изменением транспорта нужно сравнить меньшую частоту кадров и короткий
GOP с межкадровым сжатием на целевом сервере. Отбрасывание зависимых кадров
потребует отдельного механизма восстановления на IDR.
